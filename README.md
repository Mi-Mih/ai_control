# 🤖 AI Control

AI Control — локальный Telegram-бот с long polling для управления с телефона сессиями Codex, Claude Code и Cursor Agent. На каждом компьютере работает независимая установка со своим токеном бота, конфигурацией, базой SQLite, проектами и авторизацией агентов. Центральный сервер и входящие сетевые порты не нужны.

## ✨ Возможности MVP

Приложение поддерживает:

- строгий список разрешённых пользователей Telegram, работу только в личных чатах по умолчанию и ограничение частоты запросов;
- явный реестр проектов с параметрами среды Windows, Linux и WSL;
- параллельные задачи, блокировку checkout и автоматические Git worktree;
- выбор модели при создании задачи и смену модели перед следующим сообщением;
- обнаружение и подключение сохранённых сессий Codex, Claude Code и Cursor, запущенных ранее вне бота;
- ввод текстовых команд `/usage`, `/status`, `/model`, `/access`, `/approvals`, `/diff` и `/help` для открытой задачи;
- смену файловых прав завершённой задачи через Telegram в пределах локальной политики проекта;
- аварийную остановку активных задач и самого бота командой `/panic STOP` в личном чате;
- потоковый JSON-RPC через Codex `app-server`, продолжение и прерывание сессий, подтверждение действий;
- двунаправленный `stream-json` Claude Code, продолжение и прерывание сессий, подтверждение действий;
- Cursor Agent через ACP по `stdio`, продолжение и прерывание сессий, подтверждение действий;
- буферизованные обновления прогресса в Telegram и полные локальные журналы событий;
- отдельные входящие каталоги задач для изображений и документов, безопасные имена и ограничения размера;
- Git status/diff и восстановление задач после перезапуска в состояние `lost`;
- одноразовые подтверждения и раздельные политики доступа агента к файлам и отправки файлов в Telegram;
- защиту от path traversal, symbolic link, Zip Slip, ссылок внутри архивов и доступа к чувствительным файлам;
- ротацию журналов и маскирование секретов, миграции SQLite, команды первоначальной настройки и диагностики;
- блокировку второго экземпляра с тем же каталогом данных, чтобы исключить конкурирующий Telegram long polling;
- сборку Windows через PyInstaller, автозапуск через Task Scheduler, пользовательский systemd в Linux и запуск процессов внутри WSL.

В Telegram-интерфейсе намеренно отсутствует команда `/shell`. AI Control не запускает интерпретатор командной оболочки и никогда не включает для агентов режим обхода подтверждений.

## 🚀 Установка

Необходимы Python 3.12 или новее, Git и хотя бы один поддерживаемый CLI-агент. Установите [Codex](https://developers.openai.com/codex/cli/), Claude Code или [Cursor CLI](https://cursor.com/docs/cli/overview) по официальным инструкциям, затем авторизуйте каждый CLI от имени того же обычного пользователя ОС, под которым будет работать AI Control.

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev,windows,build]"
ai-control --config config.yaml setup
ai-control --config config.yaml doctor
ai-control --config config.yaml run
```

В Linux активируйте окружение командой `source .venv/bin/activate` и установите `.[dev]`.

Мастер первоначальной настройки запрашивает произвольное имя установки `INSTANCE_NAME`, токен, разрешённый ID пользователя, каталог данных, первый проект и параметры автозапуска. По возможности токен Telegram сохраняется в системном хранилище учётных данных. Если оно недоступно, используется закрытый файл `secrets.json` в каталоге данных. Токен никогда не сохраняется в SQLite.

Для каждого компьютера создайте отдельного бота через [BotFather](https://t.me/BotFather). Чтобы узнать числовой Telegram ID, обратитесь к надёжному боту для определения ID либо временно изучите ответ Bot API `getUpdates` до запуска AI Control. Не используйте один production-токен в нескольких установках.

## ⚙️ Конфигурация

Скопируйте `config.example.yaml` и отредактируйте список пользователей и проекты. Переменные окружения переопределяют имя установки, токен бота и список пользователей:

```text
INSTANCE_NAME
AI_CONTROL_BOT_TOKEN
ALLOWED_TELEGRAM_USER_IDS=123,456
```

Проекты нельзя добавлять произвольным сообщением из Telegram. Добавляйте и удаляйте их только локально, после чего перезапускайте приложение. Поле `file_access` задаёт начальный режим и одновременно локальный потолок для новых задач: `read_only` запрещает любые изменения, `project_only` ограничивает запись корнем проекта после разрешения ссылок, а `approved_paths` добавляет явно перечисленные корневые каталоги. Во всех этих режимах запросы CLI на повышение прав автоматически отклоняются. `full_access` предоставляет права обычного пользователя ОС, но включить этот режим через Telegram нельзя; для отправки внешних файлов в Telegram по-прежнему действует отдельная политика.

Режим доступа записывается отдельно для каждой задачи в момент её создания. Изменение `config.yaml` и перезапуск AI Control не повышают права уже существующей задачи. Если задача с `full_access` была понижена через Telegram, штатно вернуть ей полный доступ нельзя: убедитесь, что в локальном `config.yaml` по-прежнему указано `file_access: full_access`, перезапустите AI Control только в случае изменения конфигурации и создайте новую задачу. Если служба уже запущена с этой настройкой, достаточно создать новую задачу без перезапуска.

Для проекта WSL укажите абсолютный Linux-путь и один дистрибутив. Агент и Git запускаются внутри этого же дистрибутива через `wsl.exe --exec`; пути Windows и Linux не преобразуются и не смешиваются.

Списки моделей для кнопок Telegram задаются полями `codex.models`, `claude.models` и `cursor.models`, а выбранные по умолчанию — полями `default_model`. Модель можно сменить в карточке завершённой или остановленной задачи; новое значение применяется к следующему сообщению с сохранением истории сессии.

После открытия карточки задачи команды можно вводить прямо в чат Telegram без отдельного меню. `/usage` читает лимиты учётной записи Codex через `app-server`; для Claude фоновый интерфейс не отдаёт лимиты подписки, поэтому команда показывает токены и стоимость, зафиксированные ботом для запусков этой задачи. Cursor ACP также не предоставляет сведения о лимитах подписки. `/access` открывает выбор прав, а `/approvals` — независимый выбор между ручными подтверждениями и автопроверкой для следующего запуска завершённой или остановленной задачи. Автопроверка не расширяет файловые права. Все изменения записываются в журнал аудита. Интерактивные команды, которым нужен терминальный интерфейс или подтверждение внутри него, намеренно не выполняются.

Режимы переводятся в собственные ограничения каждого CLI: Codex получает песочницу `read-only` или `workspace-write` и рецензента `user`/`auto_review`, Cursor — режим `plan`, включённую песочницу и при необходимости `--auto-review`, Claude — `plan` для чтения либо `manual`/`auto` вместе с `--restricted` во всех режимах без полного доступа. Запрос на выход за файловую границу нельзя разрешить переключателем подтверждений: он отклоняется политикой задачи и записывается в аудит. В ограниченном режиме Claude не получает shell и другие инструменты исполнения кода.

Названия режимов описывают границу **изменений**, а не гарантированную границу чтения. В частности, песочница Codex может читать файлы вне проекта, доступные тому же пользователю ОС, даже когда не может их изменять. Для строгого ограничения чтения используйте отдельную учётную запись ОС, контейнер или виртуальную машину.

Команда `/panic STOP` доступна независимо от открытой задачи, но только разрешённому пользователю в личном чате. Она прекращает приём новой работы, останавливает активные процессы агентов и штатно завершает long polling. Пользовательская служба systemd, созданная мастером, использует `Restart=on-failure`, поэтому после такой остановки не запускается автоматически снова.

Кнопка «Подхватить сессию» ищет сохранённые сессии выбранного агента только внутри разрешённого проекта. После подключения сессия появляется как обычная завершённая задача: её можно открыть и продолжить кнопкой «Отправить сообщение». Сессии, которые прямо сейчас выполняются в другом процессе, не перехватываются — сначала завершите внешний запуск и обновите список. Бот и CLI должны работать от имени одного пользователя ОС и одной учётной записи агента.

## 🔐 Безопасность

Telegram-боты **не используют сквозное шифрование**. Не отправляйте учётные данные, закрытые ключи, профили браузера и другие чувствительные материалы. AI Control блокирует типичные чувствительные пути и отдельно запрашивает разрешение на отправку файлов вне разрешённых каталогов экспорта. Расширение файла никогда не считается доказательством его типа или безопасности.

Запускайте AI Control от имени обычного интерактивного пользователя, а не `Administrator` или `LocalSystem`. Это позволяет CLI-агентам использовать существующую авторизацию пользователя, сохраняя границы прав ОС. Кнопка разрешения привязана к пользователю, задаче, действию и конкретному запросу работающего адаптера и может быть использована только один раз. Общего действия «разрешить всё» нет.

Журналы находятся в `<data_dir>/logs`, потоки событий задач — в `<data_dir>/tasks/<id>/events.jsonl`, входящие файлы — в каталоге соответствующей задачи, а состояние — в `<data_dir>/state.db`. Журналы ротируются при достижении 5 МиБ; типичные токены, пароли и закрытые ключи маскируются.

## 🪟 Сборка и автозапуск в Windows

```powershell
python -m PyInstaller packaging/ai-control.spec --noconfirm
dist\ai-control.exe --config C:\path\config.yaml doctor
```

Spec-файл создаёт приложение без консольного окна. Для первичной диагностики можно временно убрать `console=False` из spec-файла. Мастер настройки создаёт пользовательскую задачу Task Scheduler с триггером `ONLOGON`; учётная запись `LocalSystem` не используется. Удаление задачи:

```powershell
schtasks /Delete /TN "AI Control - <instance name>" /F
```

В Linux мастер может установить `~/.config/systemd/user/ai-control.service`. Отключение: `systemctl --user disable --now ai-control`.

## 🔄 Обновление и удаление

Остановите задачу автозапуска или службу, создайте резервную копию `config.yaml` и каталога данных, установите новую сборку, выполните `doctor`, затем снова запустите приложение. Миграции базы применяются автоматически и только вперёд. Для удаления уберите задачу автозапуска или службу, исполняемый файл либо виртуальное окружение. Удаляйте каталог данных и запись `ai-control / telegram_bot_token` из системного хранилища только тогда, когда история и токен больше не нужны. Если компьютер выводится из эксплуатации или скомпрометирован, отзовите токен через BotFather.

## ⚠️ Эксплуатационные ограничения

- Возможности протоколов агентов проверяются при запуске. Если `app-server` или двунаправленный `stream-json` Claude недоступен, команда `doctor` сообщит об этом; скрытого fallback через ANSI/TUI нет.
- Файлы, полученные после запуска задачи, сохраняются в её входящий каталог. Передайте агенту показанный путь в следующем сообщении. Автоматическое внедрение вложений в середине выполняющегося хода намеренно не используется.
- Git worktree сохраняются после закрытия задачи, чтобы случайно не удалить изменения. После проверки удалите или объедините их явно средствами Git.
- После аварийного завершения AI Control нельзя повторно подключиться к прежнему дочернему процессу. Такие задачи получают состояние `lost`; сессии с сохранённым ID Codex или Claude можно продолжить в новом процессе.
- Подключение внешней сессии восстанавливает её сохранённую историю, но не управление уже работающим процессом. Определение истории Claude использует локальное хранилище Claude Code; для WSL бот должен быть запущен в той же среде, где находится это хранилище.
- Windows Job Objects оставлены как возможное дальнейшее усиление. Текущий Windows-адаптер создаёт новую группу процессов и использует `taskkill /T`, завершая дерево дочерних процессов без административных прав.

Пошаговая работа с ботом описана в [руководстве пользователя](docs/USER_GUIDE.md). Границы компонентов и модель доверия приведены в документе [«Архитектура»](docs/ARCHITECTURE.md).
