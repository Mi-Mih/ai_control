# 📘 Руководство пользователя AI Control

AI Control позволяет запускать и продолжать задачи Codex, Claude Code и Cursor Agent через личный чат с Telegram-ботом. Бот работает на вашем компьютере, использует заранее разрешённые проекты и не требует входящих сетевых подключений.

## ✅ 1. Перед началом работы

На компьютере должны быть установлены:

- Python 3.12 или новее;
- Git;
- хотя бы один из поддерживаемых CLI-агентов: Codex, Claude Code или Cursor Agent;
- выполненная локальная авторизация выбранного агента;
- отдельный Telegram-бот, созданный через BotFather.

Запускайте AI Control и CLI-агенты от имени одного и того же обычного пользователя ОС. Не используйте учётные записи `Administrator`, `root` или `LocalSystem`.

## ⚙️ 2. Первоначальная настройка

Создайте виртуальное окружение, установите приложение и запустите мастер настройки.

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev,windows]"
ai-control --config config.yaml setup
```

Linux:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
ai-control --config config.yaml setup
```

Мастер запросит:

1. название этой установки;
2. токен Telegram-бота;
3. числовой Telegram ID разрешённого пользователя;
4. каталог для базы данных, журналов и файлов задач;
5. название и абсолютный путь первого проекта;
6. необходимость автозапуска.

Затем откройте созданный `config.yaml` и убедитесь, что у каждого используемого агента задан непустой список `models` и, при необходимости, `default_model`. Готовые секции с примером формата находятся в [`config.example.yaml`](../config.example.yaml). Без списка моделей бот не сможет перейти от выбора агента к созданию задачи.

После настройки проверьте окружение:

```text
ai-control --config config.yaml doctor
```

Строки с `[FAIL]` означают, что компонент недоступен или не настроен. Исправьте обязательные проверки для используемого агента, проекта, Git и Telegram, затем повторите диагностику.

Запустите бота:

```text
ai-control --config config.yaml run
```

Если автозапуск включён мастером, последующие запуски выполняет пользовательская служба systemd в Linux или задача Task Scheduler в Windows.

## 📱 3. Начало работы в Telegram

1. Откройте личный чат со своим ботом.
2. Отправьте `/start` или `/menu`.
3. Убедитесь, что в заголовке указано ожидаемое имя компьютера.

По умолчанию бот отвечает только пользователям из `allowed_user_ids` и только в личных чатах. Если меню не появляется, проверьте Telegram ID, токен, работу процесса AI Control и результат команды `doctor`.

Главное меню содержит:

- **Проекты** — список каталогов, разрешённых локальной конфигурацией;
- **Активные задачи** — все ваши незакрытые задачи;
- **Новая задача** — создание нового запуска агента;
- **Подхватить сессию** — подключение ранее сохранённой локальной сессии агента;
- **Состояние компьютера** — доступность базы и число активных процессов;
- **Файлы** и **Настройки** — пояснение, где управлять файлами и локальной конфигурацией.

## 🚀 4. Создание задачи

Нажмите **Новая задача** и последовательно выберите:

1. **Проект**. В списке доступны только проекты из `config.yaml`.
2. **Агента**. Набор агентов ограничен настройками выбранного проекта.
3. **Модель**. Список задаётся в секции соответствующего агента в `config.yaml`.
4. **Место выполнения**:
   - **Текущий checkout** — работа непосредственно в каталоге проекта;
   - **Изолированный worktree** — отдельный Git worktree и ветка `ai-control/task-<номер>`.
5. **Текст задания**.

Изолированный worktree удобен для параллельных или рискованных изменений. Если текущий checkout уже занят другой задачей, AI Control автоматически создаёт worktree при разрешённой настройке `worktrees_enabled`. Worktree не удаляется после завершения задачи: проверьте, объедините или удалите его вручную средствами Git.

Файлы нельзя прикрепить одновременно с первым текстом задания. Сначала создайте задачу, затем загрузите файл из её карточки и отправьте агенту сохранённый путь отдельным сообщением.

## 🗂️ 5. Работа с карточкой задачи

В карточке доступны следующие действия:

- **Отправить сообщение** — продолжить ту же сессию агента с сохранением её истории;
- **Остановить** — прервать текущий запуск;
- **Статус** — показать агента, модель, состояние и рабочий каталог;
- **Git diff** — показать незакоммиченные изменения;
- **Файлы** — получить созданные или изменённые файлы;
- **Загрузить** — сохранить документ или изображение во входящем каталоге задачи;
- **Сменить модель** — выбрать модель для следующего сообщения;
- **Доступ** — выбрать файловые права для следующего сообщения;
- **Подтверждения** — выбрать ручное решение или автопроверку для следующего сообщения;
- **Закрыть задачу** — убрать её из списка активных задач.

Продолжить задачу, сменить модель, режим доступа или режим подтверждений можно после завершения или остановки текущего запуска. Если агент ожидает подтверждения, сначала ответьте на запрос.

Закрытие задачи не удаляет файлы, историю, ветку или worktree и не отменяет сделанные изменения.

### 💬 Команды открытой задачи

Сначала откройте задачу через **Активные задачи**, затем отправьте команду:

| Команда | Назначение |
|---|---|
| `/status` | Состояние, агент, модель, ID сессии и рабочий каталог |
| `/model` | Текущая и доступные модели |
| `/access` | Текущий режим файлового доступа и безопасные варианты для следующего запуска |
| `/approvals` | Ручные подтверждения или автопроверка для следующего запуска |
| `/diff` | Текущие изменения Git |
| `/usage` | Лимиты Codex или статистика запусков Claude; Cursor не передаёт лимиты подписки |
| `/help` | Краткая справка по командам |

Команда оболочки `/shell` отсутствует. Произвольные терминальные команды через Telegram не выполняются.

### 🔐 Режимы доступа

Локальное поле `file_access` проекта задаёт начальный режим и верхнюю границу, которую нельзя превысить из Telegram. Кнопка **Доступ** и команда `/access` позволяют выбрать:

- **Анализ без записи** — агент не может записывать файлы или подтверждать повышение прав;
- **Запись только в проект** — запись разрешена внутри рабочего каталога проекта, выход за него отклоняется автоматически;
- **Запись: проект + разрешённые пути** — дополнительно разрешена запись в `approved_paths`, если они настроены локально.

Полный доступ нельзя включить из Telegram. Если задача была создана с `full_access`, из чата её можно понизить, но повысить эту же задачу обратно нельзя. Режим хранится в базе отдельно для каждой задачи, поэтому изменение `config.yaml` или обычный перезапуск не изменяют её права. Запросы агента на выход за выбранную границу не предлагают кнопку «Разрешить», а автоматически отклоняются и записываются в журнал аудита.

Чтобы после понижения снова работать с полным доступом:

1. Локально проверьте, что для проекта в `config.yaml` установлено `file_access: full_access`.
2. Если вы только что изменили это поле, перезапустите AI Control. Если служба уже была запущена с `full_access`, перезапуск не нужен.
3. Создайте новую задачу в этом проекте. Она получит `full_access` как начальный режим.

История пониженной задачи в новую задачу автоматически не переносится. Штатной команды для локального повышения существующей задачи пока нет.

Кнопка **Подтверждения** и команда `/approvals` управляют отдельной настройкой:

- **Ручные подтверждения** — допустимые запросы агента приходят в Telegram;
- **Автопроверка** — штатный механизм CLI оценивает запрос и принимает решение автоматически.

Автопроверка не превращает задачу в `full_access`: режим файлового доступа продолжает действовать независимо. Менять подтверждения, как и доступ, можно только между запусками.

Эти режимы строго управляют **изменениями**. Они не обещают, что агент не прочитает доступный пользователю файл вне проекта: такая граница зависит от реализации песочницы конкретного CLI. Для строгой изоляции чтения запускайте AI Control от отдельного пользователя ОС либо внутри контейнера или виртуальной машины.

AI Control передаёт ограничения самому CLI: Codex использует свою песочницу, Cursor — `plan` и sandbox, Claude — `plan` и `--restricted`. Это полезный дополнительный барьер, но агент всё равно запускается под вашей учётной записью ОС; для жёсткой изоляции используйте отдельного пользователя, контейнер или виртуальную машину.

## 🛡️ 6. Подтверждения действий агента

Если агент запрашивает действие, требующее разрешения, задача переходит в состояние `waiting_approval`. В карточке запроса можно выбрать:

- **Разрешить один раз**;
- **Запретить**;
- **Попросить объяснить**.

Разрешение относится только к конкретному запросу, пользователю и задаче и не может быть использовано повторно. Общего режима «разрешить всё» нет. Проверяйте описание команды и путь перед подтверждением.

## 📁 7. Передача файлов

### 📥 Отправка файла агенту

1. Откройте карточку задачи.
2. Нажмите **Загрузить**.
3. Отправьте документ или изображение.
4. Бот сохранит файл и покажет абсолютный путь.
5. Нажмите **Отправить сообщение** и попросите агента использовать этот путь.

Файл сохраняется в `<data_dir>/tasks/<номер задачи>/inbox`. Файл с совпадающим именем не перезаписывается: к новому имени добавляется номер.

### 📤 Получение файла от агента

После завершения запуска нажмите **Файлы** и выберите результат. Бот показывает до 30 последних файлов, зарегистрированных для задачи или обнаруженных среди Git-изменений.

Файлы внутри рабочего каталога проекта можно отправлять сразу, если они не считаются чувствительными. Для файла вне проекта требуется одноразовое подтверждение. Чувствительные файлы, например `.env`, закрытые ключи и содержимое каталогов учётных данных, блокируются. Максимальный размер задаётся параметром `telegram_export.max_file_size_mb`.

Telegram-боты не используют сквозное шифрование. Не передавайте токены, пароли, приватные ключи, профили браузера и другие секреты.

## 🔄 8. Подключение существующей сессии

Функция **Подхватить сессию** позволяет продолжить с телефона сессию, ранее запущенную напрямую через CLI:

1. выберите проект;
2. выберите агента;
3. выберите найденную сессию;
4. откройте созданную карточку и нажмите **Отправить сообщение**.

Показываются только сессии внутри выбранного разрешённого проекта. Обозначения в списке:

- `✅` — сессия уже подключена к существующей задаче;
- `🔴` — сессия сейчас занята внешним процессом и не может быть перехвачена.

Если сессия занята, завершите внешний запуск и откройте список снова. Бот и CLI должны работать от имени одного пользователя ОС и одной учётной записи агента.

## 📊 9. Состояния задач

| Состояние | Значение |
|---|---|
| `pending` | Задача создана и ожидает запуска |
| `running` | Агент выполняет запрос |
| `waiting_approval` | Агент ожидает вашего решения |
| `completed` | Текущий запуск успешно завершён; сессию можно продолжить |
| `stopped` | Запуск остановлен пользователем |
| `failed` | Произошла ошибка; подробности показаны в карточке |
| `lost` | Процесс был потерян при перезапуске AI Control |
| `closed` | Задача скрыта из списка активных |

После перезапуска приложения выполнявшиеся задачи получают состояние `lost`, поскольку безопасно подключиться к прежнему дочернему процессу нельзя. Если у задачи сохранён ID сессии, попробуйте продолжить её новым сообщением.

## 🛑 10. Остановка и аварийное выключение

Кнопка **Остановить** прерывает одну задачу.

Для остановки всех активных задач и самого бота отправьте в личном чате точную команду:

```text
/panic STOP
```

Команда требует слово `STOP` в верхнем регистре. Пользовательская служба systemd с `Restart=on-failure` после такой штатной остановки автоматически не перезапускается.

## 🩺 11. Если что-то не работает

1. Выполните `ai-control --config config.yaml doctor`.
2. Проверьте, что CLI нужного агента установлен и авторизован под тем же пользователем ОС.
3. Проверьте абсолютный путь проекта и его параметр `runtime` (`windows`, `linux` или `wsl`).
4. Для WSL проверьте имя `wsl_distribution` и наличие проекта внутри этого дистрибутива.
5. Откройте карточку задачи: поле ошибки часто содержит непосредственную причину сбоя.
6. Изучите журнал `<data_dir>/logs` и события задачи `<data_dir>/tasks/<номер>/events.jsonl`.

Настройки проектов, моделей, локального потолка доступа, разрешённых путей и пользователей изменяются только в `config.yaml`. Режим конкретной завершённой задачи можно понизить или выбрать среди безопасных вариантов через `/access`, а режим подтверждений — через `/approvals`. `full_access` назначается только новой задаче из локальной конфигурации и не восстанавливается перезапуском для существующей задачи. После изменения локальной конфигурации перезапустите AI Control и снова выполните `doctor`.

Дополнительные сведения о конфигурации, обновлении и удалении находятся в [README](../README.md), а описание границ безопасности — в документе [«Архитектура»](ARCHITECTURE.md).
